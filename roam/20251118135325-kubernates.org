* monitoring kubernates
kubectl top needs the Metrics Server installed in the cluster:

kubectl get deployment metrics-server -n kube-system
If it is missing, kubectl top will fail even though the cluster is fine.


** List nodes (machines in the cluster)
kubectl get nodes
kubectl get nodes -o wide
Shows status, roles, Kubernetes version, internal/external IPs.

** Per-node CPU, memory, disk (capacity vs usage)
Capacity and allocatable resources (what the node has vs what Kubernetes can schedule):

kubectl describe node <node-name>
Look for sections like:

Capacity — total CPU, memory, pods, ephemeral storage
Allocatable — what is available for workloads (after system/kube reserved)
Non-terminated Pods — current requests/limits usage on that node
All nodes at once:

kubectl describe nodes
Live usage (requires metrics-server):

kubectl top nodes
Example output columns: NAME, CPU(cores), CPU%, MEMORY(bytes), MEMORY%.

** Cluster-wide workload consumption
kubectl top pods -A
kubectl top pods -A --containers
Sort by memory (example):

kubectl top pods -A --sort-by=memory
** Quick custom view (capacity in one table)
kubectl get nodes -o custom-columns=\
NAME:.metadata.name,\
CPU:.status.capacity.cpu,\
MEMORY:.status.capacity.memory,\
PODS:.status.capacity.pods,\
ALLOC_CPU:.status.allocatable.cpu,\
ALLOC_MEM:.status.allocatable.memory
** Storage (if you mean disk/PV)
kubectl get storageclass
kubectl get pv
kubectl get pvc -A
Node ephemeral storage is in kubectl describe node under capacity/allocatable.

* debuging
Run these in order — they’ll show the exact scheduling blocker.

# 1) Most useful: pod events/reason
kubectl -n prod describe pod satpay-service-prod-uid-generic-service-f6fc6bbb6-47ml2
# 2) Quick status with node assignment
kubectl -n prod get pod satpay-service-prod-uid-generic-service-f6fc6bbb6-47ml2 -o wide
# 3) Namespace events (latest at bottom)
kubectl -n prod get events --sort-by=.metadata.creationTimestamp
For Pending pods, common messages in describe are:

FailedScheduling (insufficient CPU/memory)
pod has unbound immediate PersistentVolumeClaims (PVC not bound)
node selector / taint mismatch
image pull secret issues (usually this shows after scheduled, but still check)
Since your chart uses PVC, also check storage immediately:

kubectl -n prod get pvc
kubectl -n prod describe pvc satpay-service-prod-uid-generic-service-pvc
kubectl get storageclass
